# 飯糰小店最終視覺資產與人物動畫規格

## 狀態

本文件記錄目前已落地的最終方案。人物不再使用員工 SVG，而是使用 `product/src/worker/` 的透明 PNG 動作影格；飯糰、店鋪、貨架、舞台背景與抽獎揭曉效果仍使用 SVG。

## 核心決定

- **人物：** 使用 `product/src/worker/` 的透明 PNG 影格，不重新描繪成 SVG。
- **飯糰與場景：** 使用 `product/src/img/` 的 SVG 素材；姓名與介面文字由 HTML 文字層呈現。
- **排隊補貨：** 六位店員手持飯糰由左向右排隊，隊伍逐步往右前進；最右側店員到達貨架後，先播放抬手放飯糰、再放下手的六格動作，接著保持可見、空手沿右側通道慢慢走出舞台。離場動畫與補貨週期分開運行，後續店員可以接續上架；右側離場隊伍保持與左側候補隊伍相近的間距。新店員從左側加入隊尾。
- **人物影格檔名與實際動作：** `anim-walk-01.png`–`anim-walk-08.png` 才是手持飯糰影格；`anim-carry-01.png`–`anim-carry-08.png` 是空手步行影格。檔名和動作直覺上容易看反，程式依實際圖片內容使用，不重新命名。
- **換架：** 滿架向下完全離開展示區後，空架才由下方升入；貨架交換期間排隊店員停止移動，空架完全到位才恢復補貨。
- **抽獎流程：** 屋頂艙門開啟 → 大量無姓名飯糰從屋頂向上、向左右密集噴發並飛越畫面上緣消失 → 新一波飯糰從畫面上方進入，形成鋪滿全螢幕的密集飯糰雨 → 雨幕完全落下並消退 → 每位得獎者各有一顆飯糰先停穩 → 姓名最後顯示在飯糰中央。
- **姓名：** 不出現在待機飯糰或飯糰雨中；只在得主飯糰停穩後由 HTML 文字層呈現，不烘焙在圖片中。

## 資產目錄

### 人物 PNG

位置：`product/src/worker/`

目前主舞台使用的手持與空手步行影格為 1536 × 1536 透明 PNG；新增的 `worker_put.png` 是 1024 × 1536 六格透明動作圖，已依角色輪廓仔細裁成六張 560 × 640 影格。上架影格可見高度約 526 像素、腳底基準約 y=610；程式只在播放上架影格時放大至步行影格的相同舞台顯示尺寸。

| 檔案 | 用途 |
|---|---|
| `anim-walk-01.png`–`anim-walk-08.png` | 手持飯糰的連續步行影格；補貨隊伍移動、店員進場 |
| `anim-carry-01.png`–`anim-carry-08.png` | 空手步行影格；店員放好飯糰後向右離場 |
| `anim-put-01.png`–`anim-put-06.png` | 依序播放的六張 560 × 640 上架影格；完整逐格規格見下節 |
| `worker_put.png` | 1024 × 1536 六格動作原圖；作為來源保留，主舞台使用裁切後的 `anim-put-*` 影格 |

### 上架影格裁切與尺寸基準

- 來源 `worker_put.png` 為透明六格動作圖；六張輸出依原圖閱讀順序逐格裁切，保留完整人物、手部及仍在手上的飯糰，不混入相鄰姿勢。裁切後的獨立透明殘片已清理。
- 六張輸出皆為透明 RGBA、560 × 640 畫布。可見人物高度約 524–527 px，腳底約落在 y=610；主體位置保持穩定，讓姿勢轉換時不跳動。
- 動作依序為：01 手持飯糰、02 舉起、03 舉過頭、04 伸手送出飯糰、05 放開飯糰並收手、06 手臂自然放下。程式在第 05 張顯示時將飯糰加入貨架。
- `index.js` 以 12 幀／秒播放上架序列；`.restock-worker.is-putting .worker-sprite` 暫時套用 `scale(1.184)`，補償上架圖與步行圖的透明邊界差異。切回非上架影格時移除該狀態，角色可見高度恢復一致，腳底仍對齊。

目前沒有以 `01.png`–`08.png`、`11.png`–`14.png` 或 `21.png`–`24.png` 命名的實際動畫檔案；這些編號只出現在較早的視覺規格草稿中。
### SVG 場景與物件

位置：`product/src/img/`

- `onigiri-plain.svg`：無姓名飯糰；用於貨架與得主飯糰。
- `onigiri-rain.svg`：與標準飯糰造型一致的無陰影濾鏡版本；專供大量移動的揭曉噴發與雨幕使用，避免每顆動畫粒子重複套用 SVG 陰影濾鏡。
- `onigiri-shelf.svg`：三層滿載展示架參考圖；主舞台由空架加上動態飯糰呈現補貨進度。
- `onigiri-shelf-empty.svg`：三層空架；目前補貨與換架動畫使用此 SVG。
- `onigiri-shopfront.svg`：焦糖木造店鋪、深青綠留白店招、屋頂出貨口。
- `onigiri.svg`、`onigiri-half.svg`、`shop-background.svg`：保留的舊主視覺／參考素材；目前舞台使用店鋪 SVG 與 CSS 背景，不再使用剖開飯糰揭曉效果。

舊員工 SVG（例如 `worker-teal.svg`、`worker-coral.svg`、`worker-master.svg`）已移除，不應重新加入人物流程。

## 主舞台人物動畫

實作位置：`product/src/lottery/index.js`

### 動畫流程

1. 建立空貨架，使用 `onigiri-shelf-empty.svg`；飯糰以 `onigiri-plain.svg` 逐顆疊加，容量為三層、每層十顆。
2. 六位店員手持飯糰由左向右排成一列；最右側一位是即將上架的店員。
3. 店員走向展示架時，整列其他店員也緩緩往右移動補位；手持飯糰使用 `anim-walk-01.png`–`anim-walk-08.png` 影格。
4. 店員抵達貨架後依序播放 `anim-put-01.png`–`anim-put-06.png`：舉起飯糰、伸手至貨架；第 05 張呈現放開飯糰並收手，此時才將飯糰加入貨架；第 06 張為手臂自然放下的收尾姿勢。上架期間暫時放大 PNG，使可見人物高度與步行影格一致，並以腳底對齊；接著切換空手的 `anim-carry-01.png`–`anim-carry-08.png` 影格，以穩定步速沿右側通道走到舞台外後才移除。離場動畫獨立運行，後續店員可接續上架，離場間距維持與候補隊列相近。新店員從畫面左側加入隊尾。
5. 三十個空位補滿後，隊列在貨架交換期間停住；滿載貨架必須先完全向下退出，空架再由下向上到位，之後才恢復隊列並繼續上架。
6. 抽獎期間暫停補貨時間軸，打開屋頂艙門，無姓名飯糰從艙口向上、向左右密集噴發並飛出畫面上緣；噴發飯糰消失後，再讓另一批飯糰從上方進入，形成鋪滿全螢幕的密集落雨。
7. 等所有雨滴落下、雨幕消退後，依 `winners.length` 建立得主飯糰；先讓飯糰停穩，再逐一顯示姓名。獎項名稱可在飯糰下方顯示，姓名本身保持在飯糰米白區中央。
8. 揭曉動畫結束後清除臨時飯糰，恢復店員補貨循環。

### 重要實作規則

- PNG 的透明背景由瀏覽器直接保留，不要用 CSS `mix-blend-mode` 或背景色去背。
- 人物影格實際動作：`anim-walk-*` 是手持飯糰，`anim-carry-*` 是空手向右；要依 PNG 內容使用，勿依名稱猜動作。
- 店員隊伍前進或補位時，使用持飯糰影格，以 12 幀／秒循環播放；抵達貨架後依序播放六張上架影格，僅在這段期間將 PNG 放大至與步行影格相同的可見人物尺寸，並保持腳底對齊。第 05 張呈現放開飯糰並收手，此時才新增貨架飯糰；第 06 張手臂自然放下後切換空手步行影格，同樣以 12 幀／秒循環向右離場。完全離開舞台後才移除。每位店員的離場動畫與補貨週期分開，讓右側形成間距接近候補隊列的連續人流；抽獎和貨架交換期間，候補隊伍及尚未離場的店員都要暫停。
- 飯糰雨分為兩段：先由屋頂艙口迅速噴出大量飯糰，沿緊密交錯的扇面向上、向左右持續約 2 秒；噴發飯糰逐顆越過畫面上緣並消失，不在螢幕頂端停留，也不折返下落。接著由畫面上方另起密集雨幕，以均勻交錯的隊列從上到下鋪滿全畫面，持續約 2 秒。雨幕完全消退、得主飯糰停穩前不得顯示姓名。
- 大量飛行飯糰由單一 Canvas 繪製，不建立數百個各自動畫的 DOM 元素；噴發與落雨使用不帶 SVG 陰影濾鏡的 `onigiri-rain.svg`，每顆以單次 Canvas 仿射矩陣設定位置、縮放與旋轉，避免逐粒 `save`／`restore` 狀態堆疊，並只更新目前活動中的粒子階段。粒子密度不因效能優化而降低。
- **調整揭曉時間：** 在 `product/src/lottery/animationConfig.cjs` 修改 `roofBurstDuration`（屋頂持續噴發秒數）與 `fullScreenRainDuration`（全螢幕落雨秒數）。預設各為 2 秒；這是建置時設定，修改後重新執行 `npm --prefix product run build`；不在抽獎頁面顯示操作設定，避免活動中誤觸。若瀏覽器啟用減少動態效果，程式會自動縮短這兩段動畫。
- 貨架容量以 `logisticsModel.cjs` 的 `SLOT_COUNT` 為準，必須和三層各十個位置一致。
- 抽獎結果持久化仍由既有 `/saveData` 與 `/saveLotteryResults` 流程處理；改動畫不可改動抽獎模型或得獎者名單。

## Build 複製規則

`product/webpack.config.js` 會把下列內容複製到 `product/dist/`：

```text
src/img       → dist/img
src/worker    → dist/worker
src/lottery/stage-design-prototype.html → dist/lottery/stage-design-prototype.html
src/lottery/storyboard                  → dist/lottery/storyboard
```

如果新增或替換人物影格，必須確認檔案仍位於 `src/worker/`，不需要修改 Webpack 設定。

## 重新生成 PNG 的提示詞規格

生成替換影格時，必須遵守：

- 透明 RGBA PNG。
- 依既有動畫組使用固定畫布（步行組 1536 × 1536、上架組 560 × 640），角色大小與腳底位置固定。
- 同一組影格使用同一個角色參考圖、seed 或角色一致性功能。
- 不要白底、棋盤格、地板、陰影、文字、編號、格線或浮水印。
- 不要裁切頭、手、腳或帽子。
- 不要改變臉、帽子、米白上衣、圍裙版型和焦糖棕外輪廓。
- 手持組（原檔 `anim-walk-*`）只生成雙手捧住同款飯糰的連續步行影格。
- 上架組（來源 `worker_put.png`）需保留抬手放置飯糰、放下手的連續動作；裁切後的六張 PNG 不可切到飯糰、手或人物，也不可帶入相鄰影格。
- 空手組（原檔 `anim-carry-*`）只生成放下飯糰後向右離場的步行影格。
